# 05. 訂單匯入

把 Amazon・楽天等 EC 網站訂單頁貼上的文字，建立成有品項明細的傳票。

**Language**: [日本語](05-order-import.md) | [English](05-order-import_en.md) | **繁體中文**

> **讀完這章你能做到**
> - 貼上 EC 訂單頁文字，依品項產生傳票候選
> - 在 1 張傳票內為每個品項指定不同的經費科目
> - 讓折讓列（負金額）自動歸到貸方
> - 確認・調整品項合計與訂單總額的差額
>

## 1. 這個功能的意義

信用卡 CSV 只看到「楽天市場 ¥3,280」，要依品項區分經費科目（書籍 → 新聞圖書費、消耗品 → 消耗品費等），就得手動拆分。

**訂單匯入**只要貼上訂單頁全文，AI 就會幫你抽取品項明細。

## 2. 匯入步驟

導覽列「**訂單匯入**」進入訂單匯入畫面。

### 2-1. 取得訂單頁文字

開啟 EC 網站的訂單詳細頁（不是訂單清單，而是**個別訂單的詳細內容**）。例：

- **Amazon**：訂單紀錄 → 單筆訂單的「**訂單詳細**」
- **楽天市場**：購買紀錄 → 各訂單的詳細頁
- **Yahoo! ショッピング**：訂單紀錄 → 按訂單號

頁面上全選（Mac：`Cmd+A`／Windows、Linux：`Ctrl+A`，手機・平板：長按內文選「全選」）→ 複製（Mac：`Cmd+C`／Windows、Linux：`Ctrl+C`，手機・平板：選單裡的「複製」）。

> 頁首・導覽・推薦商品・頁尾等雜訊一起複製進剪貼簿也沒關係，AI 會判別並只取需要的部分。不需要神經質地精準選擇範圍。

### 2-2. 貼上然後解析

貼到 aoiko 的「**1. 貼上訂單頁文字**」文字框（Mac：`Cmd+V`／Windows、Linux：`Ctrl+V`，手機・平板：長按選「貼上」）。

按「**解析**」送到選中的 AI 引擎解析。

#### 雲端引擎使用時

跟 [04. § 2-2](04-receipt-ocr_zh-TW.md#2-2-解析) 一樣會跳送出前確認對話框。「下次不再確認」也可以在這裡設（跟收據 OCR 共用旗標）。

### 2-3. 抽取結果確認・修正

解析完成後，「**2. 抽取結果（可編輯）**」會展開。

#### 標頭欄位（可編輯）

| 欄位 | 內容 | 例 |
|---|---|---|
| 訂單日 | 訂單確定日 | `2026-05-20` |
| 交易對象 | 網站＋店鋪 | `Amazon.co.jp` / `楽天市場 - ヨドバシ.com` |
| 訂單號 | 網站的訂單 ID（選填）| `250-1234567-1234567` |
| 合計金額（圓）| 配送料・含稅・折扣後的支付總額 | `4,580` |

#### 品項表格（可編輯）

每個品項 1 列：

| 欄 | 內容 |
|---|---|
| **品項** | 品項名（含型號・規格、可編輯）|
| **金額** | 單價×數量（整數、可編輯。折讓列用負值 `-300` 等）|
| **稅率** | 該品項的消費稅率（10%／8%，預設 10%；折扣列使用被折扣品項的稅率）|
| **科目** | 該品項要入帳的經費科目（預設 `5200 消耗品費`、下拉選擇）|
| ✕ | 刪除該列 |

下方有「**新增一列**」按鈕。AI 漏抽的品項可以手動新增。

#### 支付來源

表格下方「**支付來源（預設：未払金）**」下拉。刷卡用 `2120 未払金`（有用輔助科目分卡的話選該卡），PayPay 餘額用 `1110 現金` 或另外設定的科目。

### 2-4. 品項合計與總額不一致

按下「**建立傳票**」時，aoiko 會計算**品項合計與「合計金額」的差**。若對不上，傳票不會被建立，並顯示錯誤訊息：

> 品項合計與總額不一致（品項 ¥4,280 / 總額 ¥4,580）。請修正其中一邊後再建立傳票。

由於品項側是每個品項各記一筆借方，總額側是支付來源記一筆貸方，兩邊只要對不上，傳票本身就無法成立。請修正品項金額（例如 AI 漏抓「點數使用 -300 圓」、配送費不在品項裡、消費稅的無條件捨去或進位方式不同等）或「合計金額」欄其中一邊，再重新按一次「建立傳票」。

### 2-5. 建立的傳票結構

例：3 品項 + 配送料、合計 ¥4,580、刷卡：

```
2026-05-20  Amazon.co.jp 250-1234567-1234567
  借方  5200 消耗品費    ¥1,580   螺絲組
  借方  5200 消耗品費    ¥2,580   USB-C hub
  借方  5120 荷造運賃    ¥420     配送料
  貸方  2120 未払金     ¥4,580   合計
```

有折讓列（負值）時，會自動記到貸方：

```
2026-05-20  楽天市場 - ヨドバシ.com
  借方  5200 消耗品費    ¥3,000   商品 A
  貸方  5200 消耗品費    ¥500     優惠券折扣（同科目扣除）
  貸方  2120 未払金     ¥2,500   合計
```

> 各品項的品名會存成傳票中該品項分錄的備註（上面範例右側的文字）。各品項以含稅登錄，稅率在品項表格的「稅率」欄從 10%／8% 中選擇（預設 10%）。折扣列會以其所折扣品項的稅率登錄（所有品項同一稅率時就是該稅率；10% 與 8% 品項混在的訂單，請在折扣列的「稅率」欄選擇被折扣品項的稅率）。沒有指定適格請求書的欄位，全部以不視為適格請求書的方式登錄；需要當作適格請求書處理時，請在 [02. 建立傳票](02-journal_zh-TW.md) 手動輸入。
>
> 傳票的**來源**在內部記錄為 `paste`（傳票列表沒有依來源篩選的功能）。

## 3. 實用提示

### 品項科目分類例

| 品項例 | 推薦科目 |
|---|---|
| 書籍・電子書 | `5910 雑費`（用輔助科目分出 `新聞圖書費` 等，可在**設定 → 輔助科目**新增）|
| 文具 / 線材 / USB hub | `5200 消耗品費` |
| 業務用 PC・螢幕 | `1510 工具器具備品` → 另外當固定資產登錄（[08. 折舊](08-depreciation_zh-TW.md)）|
| AWS / SaaS 月費 | `5150 通信費`（輔助：服務名）|
| 配送料 | `5120 荷造運賃`，或併入商品科目 |
| 優惠券折扣 | 與對應商品記在同一科目，用負值（或記在 `4910 雑収入`，用正值）|

### 貼上的小撇步

- 貼上**個別訂單詳細**頁（訂單清單頁含有多筆訂單，會讓 AI 混淆）
- 一次只貼 **1 筆訂單**，並確認抽取結果的品項與金額跟貼上的訂單一致
- 整頁很長（雜訊多）也沒關係，但要確認有包含訂單摘要的部分

### Amazon Business / 楽天 Business

法人會員網站有時可直接下載「**訂單紀錄報表 CSV**」。不過 [03. CSV 匯入](03-csv-import_zh-TW.md) 只讀得了有專用解析器的格式（銀行、信用卡等），沒有訂單紀錄報表的解析器，也沒有自己指定欄位的通用解析器，所以這種 CSV 無法匯入。請一筆一筆貼上個別訂單頁，用訂單匯入處理，或到 [02. 建立傳票](02-journal_zh-TW.md) 一筆一筆手動登錄。

## 4. 抽不到時的對策

| 症狀 | 對策 |
|---|---|
| 按「解析」沒反應 | 設定 →「AI 功能」→「連線測試」確認 API 金鑰・端點 |
| 結果不是中文/日文 | 提示詞是日文，通常不會發生。使用本機 AI 時取決於所選的模型，請換成支援日文的模型 |
| 品項抽漏 | AI 限制。用「**新增一列**」手動補 |
| 金額錯 | 編輯該列。跟總額對不上的話，建立時會出現錯誤訊息，請修正品項合計或「合計金額」其中一邊 |
| 訂單號空白 | 選填，可以忽略。傳票摘要只會放交易對象 |
| 配送料・手續費沒進品項 | 用「新增一列」加配送料列（指定金額・科目）|

## 5. 隱私注意

- 訂單頁通常有**配送地址・姓名・電話**。送雲端 AI 前最後確認
- 如果混進了自宅住址，先手動刪掉文字框中含個資的行，再按「解析」會比較安全
