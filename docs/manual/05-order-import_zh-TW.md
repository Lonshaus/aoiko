# 05. 訂單匯入

從 Amazon・楽天 等 EC 網站訂單頁的貼上文字，建立有品項明細的傳票。

**Language**: [日本語](05-order-import.md) | [English](05-order-import_en.md) | **繁體中文**

> **讀完這章你能做到**
> - 貼上 EC 訂單頁文字，產生品項別的傳票候選
> - 在 1 張傳票內為每個品項指定不同的經費科目
> - 處理值引行（負金額）讓它走貸方
> - 確認・調整品項合計與訂單總額的差額
>

## 1. 這個功能的意義

信用卡 CSV 只看到「楽天市場 ¥3,280」，要按品項分經費科目（書 → 新聞圖書費、消耗品 → 消耗品費 等）就要手動拆。

**訂單匯入**讓你貼上訂單頁全文、AI 幫你抽取品項明細。

## 2. 匯入步驟

導覽列「**訂單匯入**」進入 `OrderImport` 畫面。

### 2-1. 取得訂單頁文字

開 EC 網站的訂單詳細頁（不是訂單清單而是**個別訂單的詳細**）。例：

- **Amazon**：訂單歷史 → 單筆訂單的「**訂單詳細**」
- **楽天市場**：購入歷史 → 各訂單的詳細頁
- **Yahoo! ショッピング**：訂單歷史 → 點訂單號

頁面上全選（PC：`Cmd+A`／Windows、Linux 是 `Ctrl+A`，手機・平板：長按內文選「全選」）→ 複製（PC：`Cmd+C`／`Ctrl+C`，手機・平板：選單裡的「複製」）。

> 頁眉・導覽・推薦商品・頁尾等雜訊一起進剪貼簿沒關係、AI 會判別只抓需要的。不必神經質精準選範圍。

### 2-2. 貼上然後解析

貼到 aoiko 的「**1. 貼上訂單頁文字**」textarea（PC：`Cmd+V`／`Ctrl+V`，手機・平板：長按選「貼上」）。

按「**解析**」送到選中的 AI 引擎解析。

#### 雲端引擎使用時

跟 [04. § 2-2](04-receipt-ocr_zh-TW.md#2-2-解析) 一樣會跳送出前確認對話框。「下次起不問」也可以在這裡設（跟收據 OCR 共用旗標）。

<!-- only:android -->
#### 使用裝置內 Gemini Nano（Android）時

貼上的文字和推論內容都不會離開裝置，所以不會跳確認對話框。但 ML Kit 會把 API 使用狀況（裝置型號、App 版本、每次安裝的識別碼、處理時間、錯誤代碼等）送到 Google。
<!-- /only -->

### 2-3. 抽取結果確認・修正

解析完「**2. 抽取結果（可編輯）**」展開。

#### 頭部欄位（可編輯）

| 欄位 | 內容 | 例 |
|---|---|---|
| 訂單日 | 訂單確定日 | `2026-05-20` |
| 交易對象 | 網站＋店舗 | `Amazon.co.jp` / `楽天市場 - ヨドバシ.com` |
| 訂單號 | 網站的訂單 ID（選填）| `250-1234567-1234567` |
| 合計金額（円）| 配送料・稅込・折扣後的支付總額 | `4,580` |

#### 品項表格（可編輯）

每個品項 1 行：

| 欄 | 內容 |
|---|---|
| **品項** | 品項名（含型號・規格、可編輯）|
| **金額** | 單價×數量（整數、可編輯。值引行用負值 `-300` 等）|
| **科目** | 該品項要入帳的經費科目（預設 `5200 消耗品費`、下拉選擇）|
| ✕ | 刪除該行 |

下方「**新增行**」按鈕。AI 抽漏的可手動補。

#### 支付來源

表格下方「**支付來源（預設：未払金）**」下拉。刷卡用 `2120 未払金`（有用輔助科目分卡的話選該卡），PayPay 餘額用 `1110 現金` 或另外設定的科目。

### 2-4. 品項合計與總額不一致

按下「**建立傳票**」時，aoiko 會計算**品項合計與「合計金額」的差**。若對不上，傳票不會被建立，並顯示錯誤訊息：

> 品項合計與總額不一致（品項 ¥4,280 / 總額 ¥4,580）。請修正其中一邊後再建立傳票。

由於品項側是每個品項各記一筆借方，總額側是支付來源記一筆貸方，兩邊只要對不上，傳票本身就無法成立。請修正品項金額（例如 AI 漏抓「點數使用 -300 円」、配送費不在品項裡、消費稅的無條件捨去或進位方式不同 等）或「合計金額」欄其中一邊，再重新按一次「建立傳票」。

### 2-5. 建立的傳票結構

例：3 品項 + 配送料、合計 ¥4,580、刷卡：

```
2026-05-20  Amazon.co.jp 250-1234567-1234567
  借方  5200 消耗品費    ¥1,580   螺絲組
  借方  5200 消耗品費    ¥2,580   USB-C hub
  借方  5120 荷造運賃    ¥420     配送料
  貸方  2120 未払金     ¥4,580   合計
```

有值引行（負值）時、會自動跑到貸方：

```
2026-05-20  楽天市場 - ヨドバシ.com
  借方  5200 消耗品費    ¥3,000   商品 A
  貸方  5200 消耗品費    ¥500     優惠券折扣（同科目扣除）
  貸方  2120 未払金     ¥2,500   合計
```

> 傳票的 **source** 是 `paste`（[02. § 2-1](02-journal_zh-TW.md#2-1-篩選器) 想用 source 搜尋時用）。

## 3. 實用 tips

### 品項科目分類例

| 品項例 | 推薦科目 |
|---|---|
| 書・電子書 | `5910 雑費`（用輔助科目分出 `新聞圖書費` 等，可在「**設定」→ 輔助科目**新增）|
| 文具 / 線材 / USB hub | `5200 消耗品費` |
| 業務用 PC・螢幕 | `1510 工具器具備品` → 另外當固定資產登錄（[08. 減價償卻](08-depreciation_zh-TW.md)）|
| AWS / SaaS 月費 | `5150 通信費`（輔助：服務名）|
| 配送料 | `5120 荷造運賃` or 併入商品科目 |
| 優惠券折扣 | 跟對應商品同科目用負值（或 `4910 雑収入` 用正值）|

### 貼上的小撇步

- **個別訂單詳細**頁貼上（訂單清單頁有多筆訂單會讓 AI 混亂）
- 一次只貼 **1 筆訂單**，並確認擷取結果的品項與金額跟貼上的訂單一致
- 頁長（雜訊多）OK，但要確認訂單摘要部分有包含

### Amazon Business / 楽天 Business

法人會員網站有時可直接下載「**訂單歷史報表 CSV**」。能拿到的話，也可以不用訂單匯入，改用 [03. CSV 匯入](03-csv-import_zh-TW.md) 與卡片明細分開層別匯入（沒有 Amazon Business / 楽天 Business 專用的對應格式，要的話手動每行登錄）。

## 4. 抽不到時的對策

| 症狀 | 對策 |
|---|---|
| 按「解析」沒反應 | 設定 →「AI 功能」→「連線測試」確認 API 金鑰・endpoint |
| 結果不是中文/日文 | prompt 是日文、本來不應發生。本地 AI 看模型選擇、換到支援日文的模型 |
| 品項抽漏 | AI 限制。用「**新增行**」手動補 |
| 金額錯 | 編輯該行。跟總額對不上的話，登錄時會出錯誤訊息，改品項合計或「合計金額」其中一邊 |
| 訂單號空 | 選填、無視即可。傳票摘要只會放店名 |
| 配送料・手續費沒進品項 | 用「新增行」加配送料行（指定金額・科目）|

## 5. 隱私注意

- 訂單頁通常有**配送地址・姓名・電話**。送雲端 AI 前最後確認
- 自宅住址混進去的話，把 textarea 個資行手動刪掉再按「解析」比較安全
