## 2. 備份方式比較

| 方式 | API | 對應瀏覽器 |
|---|---|---|
| **File System Access API（FSA）** | `showDirectoryPicker` | Chrome / Edge / Brave 等 Chromium 系 |
| **OPFS（Origin Private File System）** | `navigator.storage.getDirectory` + `createWritable` | Firefox / Safari 26 以後 |
| **手動 zip 匯出** | `<a download>` | 全瀏覽器 |

aoiko 會依序自動切換：FSA 可用就用 FSA，不行就改用 OPFS，再不行就只剩手動匯出。

> **早於 26 的 Safari 與 iOS 不支援自動備份。** 因為寫入 OPFS 需要的 `createWritable` 沒有實作，設定畫面備份區塊的「**狀態**」會顯示「**⚠ 不支援**」。請改用手動 zip 匯出。
<!-- /only -->

## 2. 備份的運作方式

沒有方式可以選。選一次儲存的資料夾，之後就自動寫出。不限桌面環境，所有支援的環境步驟都一樣。

## 3. 設定自動備份（推薦）

設定 → 「**備份**」區塊。
<!-- only:browser -->

### 3-1. Chromium 系（FSA 對應）

1. 按「**選擇資料夾**」
2. 瀏覽器會跳出資料夾選擇對話框
3. **隨便選一個地方**（例：`Documents/aoiko-backup/`、Google Drive 同步資料夾、Dropbox 內等）
4. 存取權限對話框按「**允許**」
5. 設定畫面的「**資料夾**」欄顯示選擇的資料夾名稱，「**狀態**」變成「**✓ 正常**」即成功

之後每次傳票新增・修改，[§ 3-6「備份要包含的項目」](#3-6-備份要包含的項目)所選的內容會自動寫出。儲存形式不是 zip，而是散檔：每次備份在 `snapshots/` 下放 1 份快照（JSON），選了「憑證照片」時，憑證照片（[02. § 1-7](02-journal_zh-TW.md#1-7-附加憑證照片)）則放在 `attachments/` 下，檔名是內容的 SHA-256。同一張照片內容相同就只會儲存一份，貼到多筆傳票上也不會重複存，內容沒變的照片之後的備份也不會重寫。

> **Google Drive / iCloud / Dropbox 連動提示**：用 FSA 指定的本機資料夾如果是雲端同步的對象，實質上就等於有了雲端備份。例：`~/Google Drive/My Drive/aoiko-backup/` → 本機寫出的 JSON 會自動同步到 Google Drive。
>
> **注意**：把 iCloud Drive 中 Finder 的「Download On Demand」項目當作 FSA 資料夾時，每次備份寫入都會觸發線上同步，可能不穩定。建議選本機有空間的地方。

### 3-2. Firefox / Safari 26 以後（只能 OPFS）

不支援 FSA 的瀏覽器只能用 **OPFS**。OPFS 是**瀏覽器內部管理的私有儲存空間**，在 Finder 或檔案總管裡看不到。

OPFS 備份：
- 自動寫入（跟 FSA 一樣每次傳票更新都寫）
- 清除瀏覽器的網站資料時，**OPFS 也會一起被清掉**（跟 IndexedDB 同命運）
- **無法達到**備份要「獨立於裝置／瀏覽器」的原本目的

> 使用 OPFS 時，強烈建議搭配**手動 zip 匯出**。

### 3-3. 早於 26 的 Safari 與 iOS（只能手動）

自動備份不會運作。設定 →「備份」的「**狀態**」會顯示「**⚠ 不支援**」，也不會出現資料夾選擇。請定期執行[§ 4 手動匯出](#4-手動匯出)。

如果你用 iPhone / iPad 記帳，建議先定好節奏（每月、每季），到了就一定手動匯出一份。

### 3-5. 刪除舊備份、刪除不再使用的憑證照片
<!-- /only -->
<!-- only:native -->
### 3-3. 刪除舊備份、刪除不再使用的憑證照片
<!-- /only -->

設定 →「備份」區塊裡有 2 個對象不同、各自獨立的刪除設定。

| 設定 | 對象 | 預設 |
|---|---|---|
| **刪除舊備份** | `snapshots/` 底下的快照本體 | 不刪除 |
| **刪除不再使用的憑證照片** | `attachments/` 底下的憑證照片實體 | 不刪除 |

「**刪除舊備份**」會把超過保留份數（最新 7 / 30 / 90 筆）的舊快照刪掉。刪除後無法復原。這個設定刪除的只有快照本體，憑證照片的實體因為可能被其他日期的快照參照，不會被這個設定刪除。不過，「刪除不再使用的憑證照片」開啟時，只被已刪除的快照參照的憑證照片，可能在同一次備份中接著被刪除（見下方）。

「**刪除不再使用的憑證照片**」會把不再被任何一份快照參照的憑證照片實體，從 `attachments/` 刪除。算作參照的，只有留在資料夾中的快照裡最新的一份，以及在指定天數（30 / 90 / 180 天）以內的快照。比這更舊的快照，即使還留在資料夾裡也不算參照。刪除是在備份之後的清理中進行，清理只在距離上次完成的清理已滿 24 小時時才會進行。因此照片會在下列兩種時機之一被刪除，並沒有「至少保留幾天」的保證：

- 參照該照片的最新快照，既不是最新的快照、也不在指定天數以內之後的第一次清理（也就是最後參照它的快照過了指定天數之後）
- 「刪除舊備份」開啟時，參照該照片的快照全部被刪除的那一次備份中的清理（距上次清理已過 24 小時以上時）

這個刪除適用於從帳簿刪掉的憑證照片，也適用於自動備份不含「憑證照片」時帳簿仍在使用的照片。不含這一項時，新的快照不會參照任何照片。這種情況下，之後從資料夾還原，被刪掉的照片不會回來。

若同一個資料夾由多台裝置共用，可能會刪掉其他裝置仍在使用的照片，天數請設長一些。
<!-- only:browser -->

### 3-6. 備份要包含的項目
<!-- /only -->
<!-- only:native -->
### 3-4. 備份要包含的項目
<!-- /only -->

在設定 →「備份」區塊的「**備份要包含的項目**」，選擇自動備份要存哪些項目。選擇的內容從下一次備份起生效。按「匯出備份」時開啟的畫面，一開始也是這個選擇（在匯出畫面所做的變更不會寫回這裡）。

| 項目 | 內容 | 預設 |
|---|---|---|
| **帳簿資料** | 傳票、會計科目、交易對象、固定資產、所得控除、預算、應收與應付、請款單、匯入規則等 | 必定包含（無法取消） |
| **憑證照片** | 只能和帳簿資料一起選擇 | 包含 |
| **業務與申報設定** | 處理年度、申報方式、消費稅、事業者資訊、家事分攤等 | 包含 |
| **AI 與外部傳送設定** | AI 引擎、傳送目的地、模型、收據讀取方式 | 包含 |
| **API 金鑰** | Gemini 與 OpenAI 相容的 API 金鑰 | 不包含 |
| **申報者資訊（利用者識別號碼・姓名・地址・稅務署）** | [01. § 3a](01-setup_zh-TW.md#3a-登錄申報者資訊青色申告特別控除xtx-提交必須)的申報者資訊 | 不包含 |

選了「API 金鑰」，API 金鑰會以未加密的形式放進備份（項目旁會顯示警告）。在自動備份選了之後，每次備份都會寫入備份資料夾，資料夾在同步資料夾裡時也會上傳到同步服務。之後取消勾選，已寫入的快照裡仍留有 API 金鑰。留下的 API 金鑰，要等到那些快照被「刪除舊備份」刪除，或手動刪除之後才會消失。如果同步服務保留了過去的版本，金鑰在那裡可能留得更久。如果無法確認含有 API 金鑰的備份是否都已刪除，請到發行方讓該 API 金鑰失效。選了「申報者資訊」的情況也一樣，取消勾選後，已寫入的快照維持原樣。
<!-- only:browser -->

存在瀏覽器內（OPFS）的備份，既看不到檔案，也無法手動刪除。只有「刪除舊備份」「刪除不再使用的憑證照片」的設定所做的刪除、設定畫面的「刪除全部資料」（[§ 6](#6-全資料刪除謹慎)），以及清除瀏覽器的網站資料，才會刪掉它們。
<!-- /only -->

取消勾選「憑證照片」後，新的快照不會再參照任何照片。這時如果「刪除不再使用的憑證照片」是開啟的，帳簿仍在使用的憑證照片也會成為刪除對象（詳見上一節）。

取消勾選「憑證照片」「業務與申報設定」「AI 與外部傳送設定」其中任何一項，自動備份的快照就會變成比這個版本更早的 aoiko 無法還原的格式。「帳簿資料」無法取消，所以對象是這 3 項。

## 4. 手動匯出

設定 → 「**備份**」區塊 → 「**匯出備份**」會開啟「**選擇要匯出的項目**」畫面。選好要匯出的項目後按「**匯出**」（項目全部取消時按不下去）：

- 所選的項目（傳票、輔助科目、交易對象、固定資產、設定、憑證照片等）匯到 1 個 zip 檔。一開始的選擇與 [§ 3 的「備份要包含的項目」](#3-設定自動備份推薦)相同
<!-- only:browser -->
- 存到瀏覽器「下載」資料夾
<!-- /only -->
<!-- only:native -->
- 桌面環境會開啟選擇儲存位置的對話框。iPad・iPhone 則存在 App 自己的儲存區，可以從「檔案」App 等取出
<!-- /only -->
- 檔名：`aoiko-ledger-{年月日}.zip` 等（不含時間，所以同一天匯出幾次都是同一個檔名）

> **API 金鑰・申報者資訊預設不會納入**。除非你在「備份要包含的項目」或「選擇要匯出的項目」選了「API 金鑰」「申報者資訊（利用者識別號碼・姓名・地址・稅務署）」，否則不會有明文 API 金鑰或個人資訊被寫進雲端同步資料夾。只有要換到另一台裝置、想連同這些一起帶走時才需要選擇。在「備份要包含的項目」選了之後，每次自動備份都會寫入，之後取消勾選，已寫入的備份裡仍然留著（[§ 3](#3-設定自動備份推薦)）。

> 少了「帳簿資料」「憑證照片」「業務與申報設定」「AI 與外部傳送設定」其中任何一項的檔案，無法用比這個版本更早的 aoiko 還原。就算 4 項都有的檔案，用比這個版本更早的 aoiko 還原時，也會先把那台裝置的設定全部清除再寫回。檔案中沒有的 API 金鑰會從那台裝置消失，免責事項的同意與「下次不再確認」的設定也會回到初始狀態。用比這個版本更早的 aoiko 執行「從備份資料夾還原」時，如果最新的快照是它無法還原的格式，就會在那裡停下，不會往前找更舊的快照。

把這個檔案：

- 複製到別的實體儲存空間（外接 SSD、USB）
- 電子郵件寄給自己（選了「API 金鑰」「申報者資訊」的檔案，內含未加密的 API 金鑰與個人資訊）
- 存到雲端儲存空間

…等，**分散儲存在多處**會比較穩妥。

> 養成在月末・季末・年末等時間點**手動匯出**的習慣，再加上自動備份，就很完整了。

<!-- only:native -->

<!-- /only -->
- 要換到新裝置
<!-- only:browser -->
- 換瀏覽器（Chrome → Safari 等）
<!-- /only -->
<!-- only:native -->
- 想換到別的裝置

### 5-2. 從備份資料夾還原

如果已經設好自動備份的儲存資料夾，按「**從備份資料夾還原**」就能讀取最新且可還原的一份備份。讀取後，選好「**要還原的項目**」，再按「**取代所選項目並還原**」（與 [§ 5-3](#5-3-從檔案還原) 步驟 4 以後相同）。

- 從新到舊掃 `snapshots/`，選出參照的憑證照片都齊全在 `attachments/` 裡的第一份快照。就算雲端同步只送到一部分照片，也會往回找到齊全可還原的一份，不用自己判斷該選哪個檔案
- 內容跟 SHA-256 對不上的憑證照片會逐張跳過（帳簿本身照常還原），跳過的張數會顯示成警告
- 雲端還沒下載到這台裝置的憑證照片，會跟壞掉的分開算，顯示成「未下載」的張數。連上網路稍等一下再重試

### 5-3. 從檔案還原

1. 設定 → 「**從備份還原**」區塊
2. 「**選擇檔案**」指定 zip（新格式）或 JSON（舊格式）——會依副檔名／內容自動判定，只有一個按鈕
3. 內容摘要顯示：
   > 版本 1 ・ 12 個表格 ・ 5,432 列
   >
   > 包含 38 張憑證照片（只有 zip 且含照片時才顯示）
4. 在「**要還原的項目**」勾選要取代的項目。只會列出備份裡有的項目，一開始已勾選的，是其中的「帳簿資料」「憑證照片」「業務與申報設定」「申報者資訊」。「AI 與外部傳送設定」「API 金鑰」一開始不會勾選，需要時再自己選。這 2 項旁邊一律會顯示下面的警告：
   > 這台裝置的設定會被備份的內容取代。只有在備份是你自己建立的時候才選擇。
5. 按「**取代所選項目並還原**」（沒有選任何項目時按不下去）
6. 確認對話框：
   > 要以備份的內容取代所選項目嗎？
   >
   > 所選項目在這台裝置上的資料會被刪除，並以備份的內容取代。沒有選擇的項目維持原狀。此操作無法復原。
7. 「**取代並還原**」執行
8. 還原成功後 App 會自動重新載入，重新載入後設定畫面會顯示結果，例如「已還原 12 個表格 / 5,432 列。」（若有憑證照片沒有實體資料，還會顯示該件數的警告）。不需要自己手動重新載入

### 5-4. 還原時注意

- **所選項目會被取代**：在「要還原的項目」選的項目，會先把這台裝置目前的資料全部刪除，再換成備份的內容。誤操作就救不回來了。沒有選的項目，這台裝置的資料維持原樣
- **備份裡沒有的值也會消失**：取代是「先刪除再寫入」，所以備份裡沒有的值，也會從這台裝置消失。例：從只含 Gemini 金鑰的備份選了「API 金鑰」，這台裝置的 OpenAI 相容金鑰也會被刪除（只有處理年度例外，備份裡沒有有效的值時會保留這台裝置的值）
- **沒有選憑證照片時**：只取代「帳簿資料」而不選「憑證照片」，這台裝置的憑證照片只會留下還原後帳簿中仍有對應傳票的部分，其餘會被刪除
- **沒有項目資訊的備份**：以前的版本匯出的備份，會依內容判斷含有哪些項目。「帳簿資料」「業務與申報設定」「AI 與外部傳送設定」一定會列出，「憑證照片」在有憑證資料表時列出，「API 金鑰」「申報者資訊」則在有這些設定值時列出。因此從沒有 AI 設定的備份選「AI 與外部傳送設定」，AI 引擎與傳送目的地會回到預設值
- **舊格式（純 JSON）裡的憑證照片**：舊的純 JSON 備份不含照片檔案本身。如果裡面只有照片的紀錄，「憑證照片」一開始就是勾選的，直接還原會把這台裝置的憑證照片換成空白的照片。想保留這台裝置的照片，請取消勾選「憑證照片」。傳票、金額等帳簿資料本身照常還原
- **每台裝置各自的設定不會跟著移動**：免責事項的同意、用「下次不再確認」等關閉的確認、備份資料夾與備份要包含的項目的選擇、儲存資料檢查的「我知道了」等，都不在備份裡，還原時這台裝置上的值也不會改變
- 還原前先把**進行中的工作手動匯出**，是個好習慣
- 還原後務必到報表確認**資產負債表是否一致**（[06. § 4-1](06-reports_zh-TW.md#4-1-不一致警告)）

### 5-5. 儲存資料檢查

設定 →「**儲存資料檢查**」區塊，會以還原備份時相同的規則，檢查這台裝置上儲存的資料。它要找的是日期無法讀取的傳票這類，雖然可以還原、卻無法正確計入合計的值。檢查本身不會修改資料。

- 結果會顯示「沒有找到不符合規則的值。」或「有 N 筆值不符合規則。」，並依資料表列出筆數與範例，按「**再檢查一次**」可以重新檢查
- 有不符合規則的值時，首頁會出現通知：「儲存的資料中有 N 筆值，目前的 aoiko 無法正確處理。」按「**查看詳情**」會開啟這個區塊，確認內容後按「**我知道了**」。針對當時的檢查結果就不會再顯示通知，檢查結果改變時會再次顯示
- 日期無法讀取的傳票（以前版本的收據辨識以 YYYY-MM-DD 以外的形式儲存日期的傳票），可以在同一區塊的清單中選擇正確的日期，按「**重新記帳**」修正。原本的傳票會以沖銷傳票取消並保留紀錄，憑證照片也會附到重新記帳的傳票上
- 其他不符合規則的值，無法在這個畫面修正。如果有以符合規則的資料匯出的備份，可以從那份備份還原

## 8. 交接資料給稅理士

設定 → 「**稅理士資料匯出**」區塊，可以匯出傳票資料的 CSV，交接給稅理士（跟備份 zip 是不同的東西——備份是用來還原 aoiko 本身的全部資料，這個是用來匯入其他會計軟體用的）。

| 檔案 | 格式 | 用途 |
|---|---|---|
| 弥生形式 CSV | 弥生インポート形式（Shift-JIS、CRLF、25 個項目） | 弥生会計、やよいの青色申告 オンライン，以及 Money Forward 雲端會計・確定申告的「弥生会計傳票匯入」都可以讀取 |
| 通用 CSV | UTF-8、每筆傳票明細一列 | 弥生形式無法使用時的備用選項 |
| 訂正紀錄（取消紀錄）CSV | UTF-8 | 沖銷傳票（原傳票・沖銷傳票）清單。主要兩個 CSV 都會把已沖銷的傳票配對從彙總中排除，需要另外確認被取消了什麼時使用 |

對象年度是設定裡「基本資訊」目前選擇的年度。

**匯出的運作方式**

- 弥生形式 CSV 在該年度沒有傳票時，不會匯出檔案，畫面會顯示「N 年度沒有傳票，因此沒有匯出檔案。」
- 弥生形式 CSV 超過 1,000 列或 1.0MB（1,000,000 位元組）時，會分成多個 CSV 並打包成 zip（`aoiko-yayoi-{年}.zip`）。請解壓縮後逐一匯入。同一筆傳票不會被拆到不同檔案
- 匯出後，會列出會受到弥生会計 オンライン或やよいの青色申告 オンライン匯入限制的傳票，並附上日期、摘要與原因。這些傳票仍原樣包含在檔案裡，匯入前請先確認。會列出的有：明細超過 20 列的傳票、含元入金的傳票（やよいの青色申告 オンライン無法匯入元入金）、金額超過 9 位數的傳票、事業主借帶有課稅銷售的傳票、因已申報年度而讓現金・預金・売掛金等的借方帶有進項稅別的傳票，以及科目・輔助科目・部門名稱較長的傳票

**弥生会計 オンライン・やよいの青色申告 オンライン的限制**

- 項目中的半形逗號，即使用雙引號括起來也無法匯入（aoiko 只在弥生形式 CSV 把它換成全形，見下方）
- 有設定交易輸入限制時，以匯入當天為基準，早於前一年度期首日（やよいの青色申告 オンライン為前一年的 1 月 1 日）的交易無法匯入
- 摘要超過 30 個字、科目名稱超過 12 個字（やよいの青色申告 オンライン為 10 個字）、輔助科目超過 15 個字的部分會被截掉。部門不會匯入
- 安裝版的弥生会計，摘要超過半形 64 位數（全形字算 2 位數）的部分會被截掉

**弥生形式 CSV 的文字處理**

- 半形逗號 `,` 換成全形的「，」，`"` 換成「”」，`;` 換成「；」，換行與 Tab 換成半形空白
- 科目・輔助科目・部門前後的空白（含全形空白）與 Tab 會被去除。零寬空白等看不見的字元不會去除
- 部門預設不輸出。只有在有帶部門的傳票時，設定裡才會出現「**匯出部門**」，勾選後才會輸出（弥生会計 スタンダード與やよいの青色申告無法匯入部門，含有部門的檔案整個都會匯入失敗）
- 貸倒引当金的 4 個科目與 4220，在弥生形式 CSV 中以較短的名稱輸出（5810 → 貸倒引当金繰入一括、5811 → 貸倒引当金繰入個別、5410 → 貸倒引当金繰入不動産、4230 → 貸倒引当金繰戻不動産、4220 → 礼金・権利金等不動産）。aoiko 本身的會計科目表不變

> **關於稅別**：弥生形式 CSV 的「稅別」欄位（課稅銷售・課稅進貨等）是 aoiko 自行推算輸出的，並非官方保證正確的規格，尤其是輕減稅率、簡易課稅事業區分等部分，匯入前請務必由會計事務所端自行確認。無適格請求書的進貨的可控除比例依弥生公開的記法顯示（100%／80%／70%／50%／30%／控不〔不可控除〕）。出售固定資產的傳票，出售對價那一列會帶一筆銷售方的稅別（簡易課稅一律第四種）。

> **弥生形式 CSV 稅別的補充**
>
> - 非課稅進貨，以及 aoiko 計算時不算入進項稅額的列（現金・預金・売掛金・未収入金・貸付金的借方等，見 [07. § 4-3](07-consumption-tax_zh-TW.md#4-3-進項稅額的彙總對象)），一律輸出「対象外」
> - 進口消費稅會輸出成「課対輸税7.8%」「課対輸税軽減6.24%」這樣（選了用途區分時為「共対」「非対」）。稅額欄留空
> - 簡易課稅時，不反映進貨與進口消費稅的用途區分，一律輸出「課対」
> - 出售業務上基本重要的一括償却資産的傳票，課稅銷售會記在出售的那項資產的科目上。無法確定是哪項資產時，維持記在事業主借，並出現在匯出後的清單中
> - 在現金・預金・應收款的借方不再算作進貨之前就已申報的年度，沿用申報時的判定輸出。該年度這些科目的借方也會帶進貨稅別，並出現在匯出後的清單中

> **用試算表開啟時的注意**：在給稅理士的 3 種 CSV 裡，以 `=`、`+`、`-`、`@`（含全形與 `−`，前面有空白的也算）開頭的值，以及以 Tab 或換行開頭的值，前面會加上 `'`，避免用試算表開啟時被當成公式執行。科目・輔助科目・部門名稱以這些字元開頭時，匯入弥生會出現名稱對照的清單。
