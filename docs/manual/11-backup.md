# 11. バックアップと復元

自動バックアップと、手動 zip の書き出し／復元の運用。

**Language**: **日本語** | [English](11-backup_en.md) | [繁體中文](11-backup_zh-TW.md)

> **この章を読み終えたら出来ること**
> - バックアップフォルダを指定して自動バックアップを有効化できる
> - 手動でバックアップファイルをエクスポートできる
> - バックアップから復元できる（証憑写真も含めて）
> - データ消失リスクと対策を理解できる
>
> **前提**：[01. 初回設定](01-setup.md) 済み。記帳をしてデータが蓄積されている状態。

## 1. なぜバックアップが必要か

aoiko のデータは **この端末の中だけ** に保存されます。サーバへ送られないので外部に漏れませんが、裏を返せば **この端末から失われたらデータも失われます**。

- ✅ サーバを介さず外部に漏れない（プライバシー）
- ❌ 端末の故障・紛失・盗難 → 復元不能
- ❌ 新しい端末への買い替え → 移行にはバックアップが必要
- ❌ **ブラウザで使っている場合**：ブラウザのサイトデータ削除・プロファイル削除 → **完全消失**
- ❌ **アプリで使っている場合**：アンインストール → OS によって挙動が違う（下記）

### アンインストールしたときの挙動（アプリの場合）

| OS | アンインストールしたとき |
|---|---|
| **macOS** | アプリのデータ領域は残る。入れ直せばデータもそのまま |
| **Windows** | **データも一緒に削除される**（ストア配布アプリの標準動作） |

> **Windows でアプリを削除・再インストールする前は、必ず [§ 4 手動エクスポート](#4-手動エクスポート)でバックアップを取り出してください。** 取り出さずに削除すると帳簿は戻りません。

定期的なバックアップは **利用者責任**です。「気付いた時に取る」運用は事故の元なので、自動バックアップと節目の手動エクスポートを併用してください。

## 2. バックアップ方式の比較

| 方式 | 使える環境 | 推奨度 |
|---|---|---|
| **アプリのフォルダ書き込み** | アプリ（Windows / macOS / iPadOS / iOS） | ◎ 自動・任意フォルダ・クラウド同期フォルダも可 |
| **File System Access API（FSA）** | Chrome / Edge / Brave 等 Chromium 系のブラウザ | ◎ 自動・任意フォルダ |
| **OPFS（Origin Private File System）** | Firefox / Safari 26 以降のブラウザ | ◯ 自動だがブラウザ管理領域 |
| **手動エクスポート** | すべての環境 | △ 思い出した時だけ |

aoiko はこの順に自動で選びます。アプリで開いていればフォルダ書き込み、ブラウザなら FSA、使えなければ OPFS、それも使えなければ手動のみ。

> **ブラウザの Safari 26 未満・iOS は自動バックアップに対応しません**（アプリで開いている場合は対象外）**。** OPFS への書込に必要な `createWritable` が実装されていないためで、設定画面のバックアップ状態は 「⚠ ブラウザ非対応」 と表示されます。手動 JSON ダウンロードのみで運用してください。

## 3. 自動バックアップを設定（推奨）

設定 → 「**バックアップ**」 セクション。使っている環境によって手順が少し違います。

### 3-1. アプリ（Windows / macOS / iPadOS / iOS）

既定で有効です。「**フォルダを選ぶ**」から保存先フォルダを指定すると、以降はそのフォルダへ自動的に書き出されます。iPhone・iPad では iCloud Drive 内のフォルダも選べます。

> **保存先フォルダの選び方が重要です。** 端末内のフォルダを選ぶと、端末そのものが失われれば自動バックアップも一緒に失われます。クラウド同期フォルダ（iCloud Drive・Google Drive・Dropbox 等）を選べば、実質そのままクラウドバックアップにもなります。

書き出される中身は 3-2 と同じ形式です。

### 3-2. Chromium 系のブラウザ（FSA 対応）

1. 「**バックアップフォルダを選択**」 をクリック
2. ブラウザがフォルダ選択ダイアログを開く
3. **任意の場所**（例：`Documents/aoiko-backup/`、Google Drive の同期フォルダ、Dropbox 内 等）を選択
4. アクセス権限のダイアログで 「**許可**」
5. 設定画面に 「**現在のフォルダ：〇〇**」 と表示されれば成功

これ以降、仕訳の追加・修正のたびに帳簿データが自動的に書き出されます。書き出し先は zip ではなく、フォルダ内の `snapshots/` にスナップショット（JSON）が 1 件、`attachments/` に証憑写真（[02. § 1-7](02-journal.md#1-7-証憑写真を添付する)）が中身の SHA-256 を名前とする実体として置かれます。写真は中身が同じなら 1 つしか置かれないため、同じ写真を複数の仕訳に貼っても実体は増えず、変わっていない写真は次回以降のバックアップで書き直されません。

> **Google Drive / iCloud / Dropbox 連携の Tip**：FSA で指定したローカルフォルダがクラウド同期対象なら、実質クラウドバックアップになる。例：`~/Google Drive/My Drive/aoiko-backup/` を指定 → ローカルに書き出された JSON が自動で Google Drive に同期。
>
> **注意**：iCloud Drive の Finder 「ダウンロードオンデマンド」アイテムを FSA フォルダにすると、バックアップ書込時に毎回オンライン同期が走るので、容量に余裕のあるローカル領域を選ぶ方が安定。

### 3-3. Firefox / Safari 26 以降（OPFS のみ）

ブラウザで開いていて FSA に未対応の場合、選択肢が **OPFS** のみになります。OPFS は **ブラウザが内部管理する非公開ストレージ**で、ファインダーや Explorer から直接見ることはできません。

OPFS のバックアップは：
- 自動で書込される（FSA と同じく仕訳更新の都度）
- ブラウザのサイトデータ削除で **OPFS も一緒に消える**（IndexedDB と同じ運命）
- バックアップとしての本来の役割（端末/ブラウザ独立）は **果たさない**

> OPFS 利用者には **手動 JSON ダウンロード**との併用を強く推奨。

### 3-4. Safari 26 未満・iOS（手動のみ）

自動バックアップは動きません。設定 → 「バックアップ」 は 「⚠ ブラウザ非対応」 と表示され、フォルダ選択も出ません。[§ 4 手動エクスポート](#4-手動エクスポート)を定期的に実行してください。

iPhone / iPad で記帳するなら、月次・四半期等の区切りで必ず手動 DL する運用を決めておくのが安全です。

### 3-5. 最終バックアップ時刻の確認

設定 → 「バックアップ」セクションに 「**最終バックアップ：2026-05-26 14:23**」 等が表示されます。長期間更新されていない場合は手動エクスポートで補完を。

### 3-6. 古いバックアップ・使われなくなった証憑写真の削除

設定 → 「バックアップ」 セクションには、対象が異なる 2 つの独立した削除設定があります。

| 設定 | 対象 | 既定 |
|---|---|---|
| **古いバックアップの削除** | `snapshots/` のスナップショット本体 | 削除しない |
| **使われなくなった証憑写真の削除** | `attachments/` の証憑写真の実体 | 削除しない |

「**古いバックアップの削除**」は、保持件数（最新 7 / 30 / 90 件）を超えた古いスナップショットを削除します。削除は元に戻せません。対象はスナップショット本体のみで、証憑写真の実体は他の日付のスナップショットからも参照され得るため削除されません。

「**使われなくなった証憑写真の削除**」は、帳簿から消した証憑写真の実体を、どのスナップショットからも参照されなくなってから指定日数（30 / 90 / 180 日）後に保存先から削除します。同じフォルダを複数の端末で共有している場合、他の端末がまだ使っている写真を消してしまう恐れがあるため、日数は長めに取ってください。

## 4. 手動エクスポート

設定 → 「**バックアップ**」 セクションの 「**バックアップをダウンロード**」 を実行：

- 全データ（仕訳、補助科目、取引先、固定資産、設定、証憑写真 等）が 1 つの zip ファイルにまとめられる
- 保存先はブラウザなら「ダウンロード」フォルダ、アプリなら保存先を選ぶダイアログが開く
- ファイル名：`aoiko-ledger-{年月日}.zip` 等（時刻は入らないため、同じ日に何度書き出しても同じ名前になります）

> **API キー・申告者情報は既定で除外されます**。「バックアップに API キーを含める」「申告者情報を含める」のトグルをそれぞれオンにしない限り、クラウド同期フォルダ等へ平文の API キーや個人情報が書き出されることはありません。別端末への移行等でこれらも一緒に持ち出したい場合のみオンにしてください。

このファイルを：

- 別の物理ストレージ（外付け SSD、USB メモリ）にコピー
- メールで自分宛て送信
- クラウドストレージに保存

…等して **複数箇所に分散**保管すると堅牢。

> 月末・四半期末・年度末等の **節目で手動エクスポート** する運用が、自動バックアップに加えて安心。

## 5. バックアップから復元

### 5-1. 復元のシナリオ

- ブラウザのキャッシュをうっかり全削除した
- Windows でアプリをアンインストールした（データも一緒に消える）
- 新しい PC に移行したい
- ブラウザを変えたい（Chrome → Safari 等）、ブラウザからアプリへ移りたい

### 5-2. 保存先フォルダから復元

自動バックアップの保存先フォルダが設定済みなら、「**保存先フォルダから復元**」をクリックするだけで復元できます。

- フォルダ内の `snapshots/` を新しい順に見て、参照している証憑写真が `attachments/` に全部揃っている一番新しい版を自動的に選びます。クラウド同期の途中で一部の写真しか端末に届いていなくても、揃っている直近の版まで遡って選ぶため、復元できるファイルを自分で探す必要はありません
- 中身が SHA-256 と一致しない証憑写真は 1 枚単位で読み飛ばされます（帳簿本体は問題なく復元されます）。読み飛ばした枚数は警告として表示されます
- クラウド同期がまだ端末に降ろしていない証憑写真は、壊れているものとは分けて「未ダウンロード」件数として表示されます。オンライン状態でしばらく待ってからやり直してください

### 5-3. ファイルから復元

1. 設定 → 「**バックアップから復元**」 セクション
2. 「**ファイルを選択**」 で zip（新形式）または JSON（旧形式）を指定 — 拡張子・内容から自動判定されるため、選ぶボタンは 1 つだけ
3. 内容サマリが表示される：
   > version 1 ・ 12 テーブル ・ 5,432 行
   > 証憑写真 38 枚を含む（zip かつ証憑写真を含む場合のみ表示）
4. 「**全データを置換して復元**」 をクリック
5. 確認ダイアログ：
   > 全データを置換しますか？
   > 現在の全データが削除され、選択したファイルの内容で完全置換されます。この操作は元に戻せません。
6. 「**置換して復元**」 で実行
7. 復元成功メッセージ → 「**再読み込み**」 でアプリ全体をリロード

### 5-4. 復元時の注意

- **完全置換**：現在の IndexedDB は丸ごと上書きされる。誤って実行したら元に戻せない
- **進行中の作業がある場合は先に手動エクスポート**してから復元する習慣を
- 復元後はレポート画面で **BS の整合性チェック**（[06. § 4-1](06-reports.md#4-1-不整合警告)）必須
- **旧形式（純 JSON）の復元では証憑写真は復元されません**（旧バックアップにそもそも写真が含まれていないため）。仕訳・金額等の帳簿データ自体は問題なく復元されます

## 6. 全データ削除（注意）

設定 → 「データ管理」→ 「**全データ削除**」：

- この端末に保存されたすべてのデータを物理削除（自分で指定した保存先フォルダのバックアップは保持）
- ブラウザで OPFS を使っている場合は、そこに置かれた自動バックアップも一緒に削除される
- 警告ダイアログ後に実行
- 削除後は初期状態に戻り、再度免責同意・基本情報入力からスタート

> **どんな時に使う？**：別のテストデータでクリーンスタートしたい、aoiko を譲渡したい、等の限定的ケース。常用しない。

## 7. バックアップ戦略の推奨

3 層構成：

| 層 | 目的 | 実装 |
|---|---|---|
| **層 1**：常時自動 | 短期保護（不慮の操作ミス対応）| クラウド同期対象のフォルダを保存先に指定する |
| **層 2**：節目手動 | 中期保護（月末・年度末等のスナップショット）| 手動エクスポート → 別の場所に保存 |
| **層 3**：定期確認 | 健全性確認 | 半年に一度、復元テストを別のブラウザのプロファイルや別の端末で実施 |

> 申告完了後の年度は特に重要。年度ロック（[06. § 8](06-reports.md#8-年度ロック申告済み)）と併用すると変更検知も効く。

## 8. 税理士へのデータ引き継ぎ

設定 → 「**税理士向けデータ出力**」 セクションから、仕訳データを税理士へ引き継ぐための CSV を出力できます（バックアップの zip とは別物。バックアップは aoiko 自身の全データ復元用、こちらは他の会計ソフトへの引き継ぎ用）。

| ファイル | 形式 | 用途 |
|---|---|---|
| 弥生形式CSV | Shift-JIS・CRLF・25 列 | **既定・推奨**。弥生会計・freee・マネーフォワード等、多くの会計ソフトの「弥生形式インポート」機能で読み込める |
| 通用CSV | UTF-8・仕訳明細 1 行ずつ | 弥生形式が使えない会計ソフト向けの予備 |
| 訂正履歴（取消履歴）CSV | UTF-8 | 訂正仕訳（原仕訳・打消し仕訳）の一覧。主要 2 つの CSV は訂正済みペアを集計から除外しているため、何が取り消されたかを別途確認したい場合に使う |

対象年度は設定の「基本情報」で選択している年度（現在の年度設定）です。

> **税区分について**：弥生形式CSVの「税区分」欄（課税売上・課対仕入等）は aoiko が独自に推定して出力しています。軽減税率・インボイス控除割合・簡易課税の事業区分等、正式な仕様として保証されたものではないため、インポート前に必ず会計事務所側でご確認ください。
