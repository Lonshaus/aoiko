# 03. CSV 匯入

從銀行・信用卡的交易紀錄 CSV 一次建立傳票。

**Language**: [日本語](03-csv-import.md) | [English](03-csv-import_en.md) | **繁體中文**

> **讀完這章你能做到**
> - 下載支援的銀行・信用卡 CSV 並匯入
> - 看懂重複檔案偵測怎麼運作
> - 用自動分類規則自動帶入對應科目
> - 用 AI 分類
> - 從匯入紀錄整批沖銷
>
> **前提**：[01. 初次設定](01-setup_zh-TW.md) 已完成。要使用依卡片區分的輔助科目（例 `2120 未払金 / 楽天卡`）時，也要先登錄。

## 1. 支援的銀行・信用卡

| 種類 | 支援 |
|---|---|
| 銀行 | 三菱 UFJ／三井住友／SBI 新生／PayPay（僅支援信用卡支付，餘額未對應）|
| 信用卡 | 楽天／JCB（含 Recruit Card 等）／セゾン／三井住友／三菱 UFJ／au PAY／PayPay／ビュー（JRE CARD）／ライフ |

## 2. 抓 CSV

從各家會員網站抓 CSV。各家入口指引：

| 服務 | 抓 CSV 路徑 |
|---|---|
| 三菱 UFJ 銀行 | ダイレクト 登入 → 入出金明細 → 期間指定 → CSV 下載 |
| 三井住友銀行 | SMBC ダイレクト → 入出金明細 → CSV |
| SBI 新生銀行 | パワーダイレクト → 入出金照会 → CSV |
| 楽天卡 | e-NAVI 登入 → 利用明細 → CSV 下載 |
| JCB / Recruit Card | MyJCB → ご利用明細 → CSV |
| セゾンカード | Net Answer → 利用明細 → CSV |
| 三井住友カード | Vpass → 明細 → CSV |
| 三菱 UFJ カード | 會員網站 → 明細 → CSV |
| au PAY カード | 會員網站 → 利用明細 → CSV |
| ビューカード | VIEW's NET → 利用明細 → CSV |
| ライフカード | LIFE-Web Desk → 利用明細 → CSV |

> **PayPay カード**：會員網站的操作流程會隨時期變動，有些帳號在網頁版下載不到 CSV，只能用 OCR 或手動輸入。
>
> **編碼**：解析器自動判斷（Shift_JIS / UTF-8）。如果亂碼請確認來源的輸出編碼。

## 3. 匯入 3 步驟

導覽列「**匯入**」進入 `Import` 畫面。

### 3-1. 步驟 1：選解析器

「**1. 解析器**」下拉選來源。選了之後「**已知側科目：{code} {name}**」會自動帶入（例：`楽天卡` → `2120 未払金`）。

如果有用輔助科目區分多個帳戶／卡片，再選擇「**輔助科目（選填）**」中對應的那一個（例：`楽天卡`）。

> 已知側科目是 CSV 每一列共通的傳票其中一邊（卡片＝未払金、銀行＝普通預金）。**對應科目**（經費・銷貨等）下一步逐列選。

### 3-2. 步驟 2：選 CSV 檔案

「**2. CSV 檔案**」選檔。

選擇之後，aoiko 會自動讀取檔案內容，並在下方顯示預覽。

#### 重複偵測

aoiko 會記每個檔案的**檔案 hash**（內容指紋）。再次匯入相同檔案會跳紅色橫幅：
> 這個檔案在 {date} 已經匯入過了（{name}）

藉此防止誤將同一個檔案重複匯入。

> 重新下載相同期間的 CSV 內容會相同，這個 hash 偵測抓得到。期間部分重疊的不同 CSV（例：上月末〜本月末 vs 本月）hash 不同，改為逐列以（日期・科目・借/貸方・金額）與既有 CSV 來源的傳票比對，疑似重複的列會自動標成「排除」（畫面上方顯示件數）。同日同額但實際上是不同的交易，可能被誤判，請確認被排除的列，確定是不同交易就取消「排除」。

### 3-3. 步驟 3：為各列選對應科目

CSV 的每一列會以**匯入候選**的形式排成表格，每列包含：

| 欄位 | 內容 |
|---|---|
| 日期 / 摘要 / 金額 | 從 CSV 讀進來的 |
| 對應科目 | 這列借方／貸方的**另一邊**（你選）|
| 輔助科目（選填）| 對應科目的輔助科目 |
| 跳過 | 勾選就不匯入這列 |

#### 帶入徽章

表格上方會顯示「**{valid} / {total} 筆 將建立**」，各列可能會出現以下徽章：

| 徽章 | 意思 |
|---|---|
| **規則** | 命中自動分類規則（見 [6 節](#6-自動分類規則)）|
| **AI↑** | AI 高信度推測對應科目 |
| **AI↓** | AI 推測但信度低、建議確認 |
| （無徽章）| 沒有自動帶入、需要手動選 |

把滑鼠移到每個徽章上面可以看詳細。AI 徽章只有在設定了 AI 功能時才會出現。

#### 列表確認

- **規則**徽章基本上可以直接信任，不用更動
- **AI↑** 看一眼確認是否妥當
- **AI↓** 一定要確認
- 沒有徽章的列，**對應科目**要自己選

### 3-4. 登錄

按「**建立 {count} 筆**」會不經確認，一口氣把全部列變成傳票。

> 按下去之前，請先仔細確認數量與徽章。錯了可以用沖銷傳票補救，但量大時會很辛苦。
>
> 發現大量誤登錄時，從導覽列「**匯入紀錄**」做**整批沖銷**（[5 節](#5-匯入紀錄與整批沖銷)）比較有效率。

成功時上方會顯示「**已建立 {count} 筆傳票**」。

## 5. 匯入紀錄與整批沖銷

導覽列「**匯入紀錄**」進入 `ImportHistory` 畫面。歷次匯入依時間順序排列。

每個批次列：

| 欄位 | 內容 |
|---|---|
| 匯入時間 | 什麼時候匯入的 |
| 解析器 | 用哪個解析器（楽天卡 等）|
| 檔名 | 原 CSV 檔名 |
| 件數 | 批次建立的傳票數 |
| 狀態 | `有效 N` / `全部已沖銷` / `有效 X / 沖銷 Y`（部分沖銷）|

### 整批沖銷

按某列展開 → 「**整批沖銷（{count} 筆）**」按鈕。

> 確認對話框：「這個批次建立的有效傳票全部標記『已沖銷』。各傳票會建一張對應的沖銷傳票，兩邊都保留為歷史紀錄」

按下去一次產生所有沖銷傳票，批次狀態變「**全部已沖銷**」。原傳票保留為歷史（電子帳簿保存法要件）。

> 匯錯 CSV，或已知側科目選錯時，可以用這個功能一次全部回復，再重新匯入。

## 6. 自動分類規則

設定 → 「**自動分類規則**」區塊登錄**符合內容字串就帶入對應科目**的規則。

### 6-1. 規則欄位

| 欄位 | 內容 |
|---|---|
| 比對方式 | `內容包含` / `交易對象名稱一致` / `正規表示式` |
| 比對字串 | 要比對的字串（例：`amazon`、`/^電気料金/`）|
| 對應科目 | 命中時要帶入的科目（例：`5200 消耗品費`）|
| 輔助科目（選填）| 同上的輔助科目 |
| 交易對象（選填）| 命中時順便帶入的交易對象 ID |
| 優先度 | 數字大的規則先評估。多筆命中時，以優先度高的為準 |

### 6-2. 登錄例

| 比對字串 | 對應科目 | 用途 |
|---|---|---|
| `amazon` | 5200 消耗品費 | Amazon 出費 → 消耗品費 |
| `AWS` | 5150 通信費（輔助：AWS）| AWS 每月帳單 |
| `ネットフリックス` | 5150 通信費 | 訂閱費 |
| `Adobe` | 5150 通信費 | Creative Cloud 月費 |
| 正規表示式 `/電気|TEPCO/` | 5130 水道光熱費 | 電力公司彙總 |

### 6-3. 規則在哪起作用

- **CSV 匯入時**：命中規則的列會出現**規則**徽章，並自動帶入對應科目
- 命中規則的列**不會再問 AI**（考量成本・速度・正確性）

> 規則愈多，CSV 匯入手動工作量趨近零。從常出現的交易開始登起。
